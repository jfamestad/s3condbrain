Hard delete {{ path }}

This page deletes nothing. A person performs these steps under the break-glass role; every assumption of that role is alarmed. No function, tool or button in this system can delete a version — by design, not by omission. Viewing this page has been logged.

When it is warranted: content that must not exist in any version, or a legal request. Not for "it is untidy" — that is archiving, which any writer can do. Deletion, like revocation, is prospective: it does not pull text back out of anyone's conversation.

Procedure (RUNBOOK §3)

  1. Open a ticket — anything with a date and your name: the path, the version ids (all of them, above), why, who asked. The alert email that arrives when you assume the role is the second half of the record; keep both.
  2. Assume the break-glass role. In the console: switch role, account id, role name wiki-<env>-break-glass. Or on the CLI (the role ARN is the BreakGlassRoleArn stack output; the session name lands in CloudTrail, so put the ticket in it): 
    CREDS=$(aws sts assume-role --role-arn <BreakGlassRoleArn> \
  --role-session-name "hard-delete-$(date +%Y%m%d)-<ticket>" --query Credentials --output json)
export AWS_ACCESS_KEY_ID=$(jq -r .AccessKeyId <<<"$CREDS") \
       AWS_SECRET_ACCESS_KEY=$(jq -r .SecretAccessKey <<<"$CREDS") \
       AWS_SESSION_TOKEN=$(jq -r .SessionToken <<<"$CREDS")
  3. List every version, delete markers included, and compare with the table above: 
    aws s3api list-object-versions --bucket {{ bucket }} --prefix "{{ key }}" \
  --query '{v:Versions[?Key==`{{ key }}`].VersionId, d:DeleteMarkers[?Key==`{{ key }}`].VersionId}'
  4. Delete each version. In production the versions are under Object Lock governance retention; the flag must be passed or S3 refuses. In dev (no Object Lock) omit --bypass-governance-retention. 
    {{ delete_commands }}

    delete-object without --version-id only adds a delete marker; that is not a hard delete.

  5. Confirm the listing in step 3 is empty, then unset AWS_ACCESS_KEY_ID AWS_SECRET_ACCESS_KEY AWS_SESSION_TOKEN (or sign out of the switched role).
  6. The folder's _listing.json still names the article until the next rebuild; any write in that folder forces one. Search follows the listing.
  7. Close the ticket with the alert email attached and the count of versions removed. Note whether the content had reached anyone's context before the delete.

Why the role has no PutObject: so a break-glass session cannot quietly rewrite history as well as erase it. Restores are RUNBOOK §1.
